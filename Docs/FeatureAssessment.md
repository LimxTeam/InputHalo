# InputHalo 后续功能评估

评估日期：2026-09-23。以下是基于当前代码、已完成的用户迭代和公开产品资料的产品判断，
不是已实施功能，也不是市场需求或竞品性能的实测结论。

后续实施更新：本地方案与导入导出、前台应用排除、精确快捷键隐藏，以及矩形/箭头/椭圆与右键撤销现已接入。
下表保留当时的评估顺序，已接入项的使用说明见 [方案与排除规则](PresetsAndExclusions.md)。

## 判断

现有核心功能已能完成“操作可视化＋临时标注”。下一步应先减少演示过程中的操作成本，
再增加新的绘制工具。保持紧凑设置、按住即用、松开清理的特点。

微软 PowerToys 已覆盖指针定位、点击高亮、应用排除等能力；ZoomIt 已提供缩放、标注和录屏。
单纯追加更多光圈样式或把录屏也做进来，很难形成清晰区别。
资料：[Mouse utilities](https://learn.microsoft.com/en-us/windows/powertoys/mouse-utilities)、
[ZoomIt](https://learn.microsoft.com/en-us/sysinternals/downloads/zoomit)。

## 推荐顺序

| 优先级 | 功能 | 为什么值得做 | 第一版范围 | 相对工作量 |
| --- | --- | --- | --- | --- |
| P0 | 一键暂停/恢复全部提示 | 演示敏感内容或切换工作时，不必去找托盘 | 可配置全局快捷键、暂停状态提示；不启用密码识别承诺 | 小 |
| P0 | 方案预设与导入导出 | 教学、会议、录屏使用不同配色、大小和快捷键 | 3 个本地方案、复制、重命名、JSON 导入校验；不保存输入历史 | 中 |
| P0 | 应用排除列表 | 降低游戏、远程桌面等场景的快捷键和提示干扰 | 按前台进程精确匹配；默认清单为空；不会读取文档正文 | 中 |
| P1 | 标注撤销与形状扩展 | 已有连续框选，误画后需要单独撤销 | 保持快捷键期间撤销最后一笔；箭头、椭圆；保持松开清除原则 | 中 |
| P1 | OBS/录屏兼容说明与检查页 | 用户看到不代表观众录到，容易产生售后问题 | 解释显示器/窗口/游戏采集区别；本地状态和可复制诊断信息；不保证所有采集方式 | 中 |
| P1 | 手动检查更新＋签名验证 | 商业版本需能可靠维护 | 明确触发、显示更新说明、验证签名、不静默替换程序 | 中到大，依赖发布服务 |
| P2 | 临时聚光灯 | 演示时快速强调局部区域 | 按住触发、背景调暗、松开恢复 | 中 |
| P2 | 放大镜 | 对小字号教学有帮助 | 先做独立技术验证，处理 DPI、截图递归与捕获兼容 | 大 |

PowerToys 的应用排除设置说明这类产品存在按应用控制的实际设计需求；
是否适用于 InputHalo 的目标客户仍应通过用户反馈验证。
资料：[Find My Mouse settings](https://learn.microsoft.com/en-us/windows/powertoys/mouse-utilities#find-my-mouse)。

OBS 明确区分显示器采集、窗口采集和游戏采集。因此建议先做好说明与兼容矩阵，
不要在未验证前承诺“所有录屏软件都能捕获透明叠加层”。
资料：[OBS Sources Guide](https://obsproject.com/kb/sources-guide)。

## 商业交付优先于功能扩张的部分

正式发布前完成受信任签名、版本渠道、真实支持入口、授权条款、安装/卸载元数据。
这些是发布准备，不等于立即增加联网激活或订阅。
当前程序没有账号、遥测、在线激活和更新请求；新增相应服务前应明确数据与服务约定。

## 暂缓

账号云同步、内置商店、主题市场、完整录屏、视频剪辑、任意桌面对象识别。
这些能力会大幅扩张维护范围，现阶段没有足够用户证据支撑。

本地方案等上述功能落地后，建议先收集手动使用反馈，再考虑全局一键暂停及录屏兼容说明。
